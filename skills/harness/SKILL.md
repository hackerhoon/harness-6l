# Harness — 6계층 에이전트 하네스 엔지니어링

**Agent = Model + Harness.** 모델은 추론을 제공하고, 하네스가 나머지 전부를 제공한다: 알려진 실패를 막는 가이드, 새 실패를 잡는 센서, 유한한 에이전틱 루프, 지속되는 메모리, 강제되는 권한, 완전한 관찰가능성.

이 스킬이 만드는 것은 **Outer harness**다 — 제품팀이 모델 주위에 직접 만드는 설정·라우팅·검증·정책. 모델에 내장된 Inner harness(기본 안전층, 네이티브 도구 호출)는 대상이 아니다. 범위를 이렇게 못박지 않으면 하네스 작업은 무한대로 번진다.

**하네스의 범위 정의(배경 에이전트 규칙):** 인간은 의도를 제공하고, 결과를 검토하고, 에스컬레이션을 처리한다. **그 사이의 전부가 하네스다.**

## 시작 전: 하네스 결정 필터

하네스는 공짜가 아니다. 다음 5문항에 답한 뒤에 시작한다.

| # | 질문 | 예이면 필요한 계층 |
|---|------|------------------|
| 1 | 같은 워크플로를 **반복** 실행하는가? | 전체 |
| 2 | 에이전트가 조용히 틀린 결과를 내면 **알아차리겠는가?** 아니라면 | L2 센서 |
| 3 | 다음 세션에 같은 컨텍스트를 **다시 설명**해야 하는가? | L4 메모리 |
| 4 | 실수가 **외부 결과**(배포, 발송, 삭제)를 만드는가? | L5 권한 |
| 5 | **이 작업의 성공을 무엇으로 판정하는가? 그 판정은 관찰 가능한가?** | — 아래 참조 |

**1~4가 전부 아니오면 하네스를 만들지 않는다.** 단일 턴 질문, 창의적 브레인스토밍, 탐색적 대화, 일회성 작업은 대화 자체가 하네스다. 이 경우 "하네스 불필요"와 그 근거를 답하고 종료한다. 만들지 않는 것도 이 스킬의 정당한 산출물이다.

**5번에 답할 수 없으면 하네스 구축을 시작하지 않는다.** 잘못 정의된 목표를 둘러싼 완벽한 하네스는 **신뢰성 있는 쓰레기**를 생산한다. 수용 기준이 틀리면 센서가 틀린 출력을 검증한다. 하네스는 빌더가 선택한 목표와 평가를 **증폭**한다 — 시스템이 틀린 것을 최적화하면 하네스는 에러의 규모를 키운다. 5번의 답을 먼저 사용자와 확정하고, 그 답을 산출물 어딘가에 문자로 남긴다.

## 6계층과 강제성

계층마다 신뢰도가 다르다. **같은 실패를 더 강한 계층에서 고치면 더 오래 간다.**

| 계층 | 역할 | Claude Code 실현 수단 | 강제되는가 |
|---|---|---|---|
| **L1 가이드** | 피드포워드 — 실행 전 알려진 실패 예방 | `CLAUDE.md`, `.claude/rules/*.md` (`paths:` 스코프) | 아니오 — 컨텍스트이지 강제 설정이 아니다 |
| **L2 센서** | 피드백 — 실행 후 실패 포착 | 프로젝트 test/lint/typecheck를 루프에 배선, hook | 종료코드로 관측, hook으로 차단 |
| **L3 루프** | 계획·실행·검증·수정 + 유한 재시도 | 서브에이전트 `maxTurns`, `PostToolBatch` hook | 부분 — 아래 강제성 표 참조 |
| **L4 메모리** | 세션 간 상태 지속 | `_workspace/` 파일 | 플랫폼 마찰 없음 |
| **L5 권한** | 안전 경계 | `settings.json` deny/ask/allow, PreToolUse hook, 샌드박스 | **예 — 유일하게 완전 강제되는 계층** |
| **L6 관찰가능성** | 추적·경보·회귀 포착 | transcript, hook 원장, OTel, `-p --output-format json` | 아니오 — 관측 계층이다 |

**핵심 대응 관계:** `CLAUDE.md`는 강제가 아니다(문서 원문: "context, not enforced configuration"). **반드시 실행돼야 하는 규칙은 CLAUDE.md가 아니라 hook으로 쓴다.** 이것이 통제 신뢰도 사다리를 Claude Code로 옮길 때의 가장 중요한 변환이다.

### 강제성 확정표 — 모든 예산 라인에 `enforced_by`를 붙인다

문서에 "COST: max $5"라고 적는 것과 실제로 $5에서 멈추는 것은 다르다. 그 차이를 숨기면 하네스는 **안전으로 위장한 병목**이 된다. 따라서 산출하는 모든 예산·제약 라인에 `enforced_by: settings | hook | subagent | sandbox | -p-flag | none` 을 반드시 단다.

| 제약 | Claude Code 실제 | `enforced_by` |
|---|---|---|
| ALLOW read/write/execute | `permissions.allow` | `settings` |
| ASK before (푸시·배포·발송) | `permissions.ask` (평가 순서 deny→ask→allow, 첫 매치 확정) | `settings` |
| DENY (rm -rf, 비밀 읽기, 외부 발송) | `permissions.deny` + `rm`/`rmdir` critical-path 회로차단기 | `settings` (이중) |
| 작업당 최대 쓰기 N회 | 네이티브 없음 → PreToolUse hook 카운터 | `hook` |
| 최대 소요시간 / 도구 호출 / 토큰 | 네이티브 없음 → `PostToolBatch` hook `exit 2` | `hook` |
| 단계당 재시도 3회 | 서브에이전트 frontmatter `maxTurns` | `subagent` |
| 새 도메인 접촉 차단 | `sandbox.network.allowedDomains` + `strictAllowlist` | `sandbox` |
| 비용 $5/task | 대화형에 등가 설정 **없음**. `claude -p --max-budget-usd 5`에서만 강제 | `-p-flag` / 대화형은 `none` |
| 신뢰/비신뢰 입력 분리 | 네이티브 프리미티브 없음. 가이드 + 행동반경 축소의 조합 | `none` + 부분 `settings` |

**`enforced_by: none`인 라인은 스코어카드에서 분리 집계한다.** 그것은 "환경 제약"이 아니라 "가이드"이며, 지켜지지 않아도 아무도 막지 않는다. 정직하게 표기하는 것이 이 설계의 중심 장치다.

> 실제 문법·우선순위·hook 스크립트 전문은 `references/enforcement.md`를 읽어라. 계층별 규범과 판단 기준은 `references/layers.md`.

## 워크플로: 5단계

| # | 단계 | 하는 일 | 종료 조건 | 계층 |
|---|---|---|---|---|
| 1 | **SCOPE** | 결정 필터 + 기존 자산 감사 + drift/dangling 검사 → **필요 계층 목록** 산출 | 필요 계층 목록과 감사 결과가 사용자에게 보고됨 | 진입 |
| 2 | **GROUND** | `CLAUDE.md`에 build/test/lint **정확한 명령**을 적고 **실제로 실행해 종료코드를 확인** | 3개 명령의 종료코드가 관측됨 | L1+L2 |
| 3 | **WIRE** | 기존 test/lint를 에이전트 실행 루프에 배선 + `settings.json` 권한 라인 **제시** | 자기검증 루프가 에이전트 정의에 기술됨 + 권한 라인 제시됨 | L2+L5 |
| 4 | **BUILD** | 에이전트·스킬·오케스트레이터 생성 + `_workspace/harness.md` 생성 | 파일 생성 완료 + **미검증 표식** 기재 | L3+L4 |
| 5 | **RATCHET** | 실패 1건마다: 재현 → 클래스 분류 → 가장 강한 계층 1곳 수정 → 원장 한 줄 → 재발 확인 | 원장에 한 줄 추가 + 재발 없음 확인 | 전 계층 |

**4단계는 게이트 뒤에 있지 않다. 즉시, 무조건 실행한다.** 에이전트 팀과 오케스트레이터를 "성숙도 조건을 채운 뒤에" 주는 설계는 실행의 산물을 실행의 전제조건으로 거는 것이며, "실행하고, 실패를 관찰하고, 실제 증거에서 하네스가 자라게 하라"는 원칙의 인과를 뒤집는다. 대신 **미검증 표식**을 붙인다 — 부분 실패를 유창한 최종 답변 뒤에 숨기지 않기 위해서다.

### 진입 경로 4종 — 항상 1단계부터 밟지 않는다

진입점은 계층 번호가 아니라 **관찰된 실패가 가리키는 계층**이다. 이미 신뢰성이 증명된 계층을 다시 증명하라는 요구는 순손실이다.

| 프로젝트 상태 | 경로 |
|---|---|
| 신규 / 하네스 계층 0개 | 1 → 2 → 3 → 4 → 5 |
| 성숙 (테스트·린터·CI 보유) | 1 → **3** → 4 → 5. 2단계는 **종료 테스트 선실행 → 통과 시 즉시 종료 처리** |
| 관찰된 실패가 명확 | 1 → **5 직행**. 비용 예측 불가면 예산부터, 범위 초과면 권한부터 |
| 기존 하네스 운영 | 1(drift 감사) → 5 |

**"건너뛰기"가 아니라 "종료 테스트를 먼저 실행해 통과하면 그 단계를 종료 처리"다.** 이렇게 하면 "각 계층이 신뢰성을 증명한 뒤에만 계층을 늘린다"는 원칙이 유지된다.

### 각 단계 상세

**1 SCOPE.** 결정 필터 5문항에 답한다. 동시에 다음을 감사한다:
- `CLAUDE.md`, `.claude/agents/`, `.claude/skills/`, `.claude/settings.json`, `_workspace/` 존재 여부 → 계층별 충족 판정
- **drift**: 파일에 있는 에이전트/스킬 목록과 오케스트레이터가 기술한 구성의 불일치
- **dangling**: 권한 규칙·hook 명령·체크포인트 참조·가이드가 지시하는 파일이 **실재하는가**. 존재하지 않는 경로를 가리키는 규칙은 있으나 마나다
- **무효 권한 규칙**: `Write(경로)`·`Glob(경로)`·`MultiEdit(경로)`·`NotebookEdit(경로)` 형태는 수락되지만 **조회되지 않는다**. 발견하면 `Edit(...)`/`Read(...)` 형태로 정정할 것을 **제시**한다
- **가이드 위생**: 날짜 없는 규칙, 센서가 이미 강제하는 규칙, 상충하는 규칙 쌍
- `model: "opus"` 같은 하드코딩된 모델 강제

감사 결과를 요약 보고하고 실행 계획을 확인받은 뒤 진행한다. **settings.json은 직접 고치지 않는다**(아래 참조).

**2 GROUND.** `CLAUDE.md`가 L1 가이드 **본체**다. 포인터만 담는 파일이 아니다. 최소 구성: 프로젝트명, 언어, **정확한** BUILD/TEST/LINT 명령, 규칙, 안티패턴(각 항목에 날짜). 규칙은 0개로 시작한다 — 신규 프로젝트에는 아직 관찰된 실패가 없으므로 규칙을 지어내면 그 자체가 나쁜 가이드다. 규칙은 5단계가 채운다.
명령을 적었으면 **실제로 실행해 종료코드를 확인한다.** 5단계 전체에서 결정적으로 검증 가능한 유일한 관문이다.

**3 WIRE.** 이미 있는 센서(프로젝트 테스트·린터·타입체커)부터 루프에 배선한다. 새 센서를 만들기 전에 있는 것을 쓴다. 계산적 센서가 안정적으로 에러를 잡은 뒤에만 추론적 센서(LLM 심판)를 고려한다.
권한은 `settings.json` 라인을 **작성해 제시하고 사용자 승인을 받는다.** 미승인이어도 진행한다(비차단).

**예산을 문서가 아니라 실제로 강제해야 하면 hook을 설치한다.** 설치하지 않으면 그 예산의 `enforced_by`는 `none`이며, 상태 파일에 `none`이라고 적는다 — 설치하지 않은 hook을 `enforced_by: hook`으로 적는 것이 이 필드가 막으려는 바로 그 거짓말이다.

```bash
mkdir -p .claude/hooks
cp "${CLAUDE_SKILL_DIR}"/assets/hooks/*.sh .claude/hooks/
chmod +x .claude/hooks/*.sh
command -v jq >/dev/null || echo "jq 없음: 쓰기 한도와 토큰 예산은 enforced_by=none 이다"
```

설치했으면 `settings.json`의 `hooks` 블록도 함께 제시한다(등록 JSON은 `references/enforcement.md`). `audit_log.sh`는 **`PostToolUse`와 `PostToolUseFailure` 양쪽에 등록한다** — `PostToolUse`는 도구가 성공했을 때만 발화하므로 한쪽에만 걸면 원장의 `ok`가 항상 true가 되어 완료율과 복구시간을 잴 수 없다.

**4 BUILD.** 에이전트 정의·스킬·오케스트레이터를 생성한다. `_workspace/harness.md`를 만든다. 모든 산출물에 미검증 표식을 붙인다.

**5 RATCHET.** 실패가 발생할 때마다 6단계 루프를 돈다. 상세는 `references/ratchet.md`.

## 산출물

```
{project}/
├── CLAUDE.md                       L1 가이드 본체 (+ 하네스 섹션)
├── .claude/
│   ├── rules/*.md                  L1 — 규칙이 커질 때 paths: 스코프로 분할
│   ├── agents/*.md                 L3 — 빌트인 타입을 쓰더라도 정의 파일은 만든다
│   ├── skills/*/SKILL.md           L3
│   ├── settings.json               L5 — 라인을 제시하고 사용자가 승인한다
│   └── hooks/*.sh                  L5+L3 — 강제가 필요한 예산만
└── _workspace/                     L4 — 단일 상태 저장소
    ├── {phase}_{agent}_{artifact}.{ext}
    ├── harness.md                  ## 체크포인트 / ## 래칫 원장 / ## 성숙도
    └── runs/{session_id}.jsonl     hook을 설치했을 때만 생성
```

**상태 저장소는 `_workspace/` 하나다.** 두 번째 저장소를 만들지 않는다 — 여러 저장소는 어느 것이 진실인지 모르게 만든다.

**체크포인트는 활성 작업당 최신 1개만 유지한다.** 덮어쓰기가 곧 만료다. 3주 전 체크포인트가 없어진 파일과 번복된 결정을 참조하면 에이전트는 낡은 상태로 판단한다. 산출물 아티팩트는 보존하되 체크포인트는 최신 1개로 유지한다.

### `.claude/settings.json`은 에이전트가 직접 쓰지 않는다

이것은 방침이 아니라 **플랫폼 사실**이다. `.claude`는 protected directory이고, `permissions.allow`에 `Edit(.claude/**)`를 넣어도 **사전승인되지 않는다**(안전검사가 allow 평가보다 먼저 실행된다). 따라서 하네스는 **적용할 라인을 작성해 사용자에게 제시**하고, 적용은 사용자가 한다. 제시할 때는 각 라인이 무엇을 막는지와 `enforced_by`를 함께 쓴다.

### CLAUDE.md 하네스 섹션에 반드시 넣을 문장

> **이 파일과 대화가 충돌하면 이 파일이 이긴다.** 대화 중의 교정은 세션이 끝나면 사라지지만 이 파일의 규칙은 모든 향후 실행에 적용된다. 규칙을 바꾸려면 대화가 아니라 이 파일을 바꾼다.

이 권위 역전이 없으면 산출된 가이드는 세션 종료 시 소실되는 대화 교정과 다를 바 없다. 템플릿은 `assets/claude-md-harness-section.md`.

## 기존 하네스 마이그레이션

기존 하네스를 가진 프로젝트에서 이 스킬이 트리거되면:

1. **`_workspace/`가 있으면 그대로 쓴다.** 이동·삭제하지 않는다. `harness.md`만 추가한다.
2. **기존 `.claude/agents/`·`.claude/skills/`는 L3 충족으로 인정한다.** 다시 만들지 않는다.
3. **`CLAUDE.md`가 포인터만 담고 있으면 L1 승격을 제안한다** — build/test/lint + 규칙 + 안티패턴. **자동으로 바꾸지 않고 제안한다.**
4. 변경 이력이 2컬럼이면 4컬럼(날짜/변경 내용/대상/사유)으로 이관을 제안한다.
5. dangling·무효 권한 규칙 목록을 제시한다. **직접 수정하지 않는다.**
6. `model: "opus"` 하드코딩을 발견하면 정정을 제안한다.

기존 하네스에 **에이전트 하나를 추가하는 요청**은 1단계 감사 후 곧바로 4단계로 간다. 게이트나 빌드 경로를 통과시키지 않는다.

## 무인 운영 승격 게이트

에이전트를 사람 없이 돌리기 전에만 적용한다. 팀 생성이나 오케스트레이터 생성을 막는 게이트가 아니다. `_workspace/harness.md`의 `## 성숙도` 섹션에 체크박스로 상주하며, **실사용이 채운다.**

먼저 센서 커버리지 5문항(모두 예여야 한다):
인간 검사 없이 에이전트가 자기 출력을 검사할 수 있는가 / 모든 중요 출력에 계산적 센서가 최소 1개 있는가 / 센서 결과가 추세 분석용으로 기록되는가 / 에이전트 동작이 변해도 센서는 안정적인가 / 어떤 센서도 건드리지 않고 조용한 회귀가 사용자에게 도달할 수 있는가.

그다음 실적 6조건:
- [ ] 수동 교정 없는 완료율 ≥ 80%
- [ ] 어떤 작업도 예산을 초과하지 않음
- [ ] 에이전트가 최소 1회 **올바르게 에스컬레이션**함
- [ ] 체크포인트가 최소 1회 재시작에서 생존함
- [ ] 트립와이어가 최소 1회 발화함 (시뮬레이션 가능)
- [ ] 권한 경계가 최소 1회 행동을 차단함

### 진짜 지표는 하나다

모델 호출·토큰·메시지를 세지 마라. **수동 개입 없이 완료되고 수용 가능한 증거를 낸 작업 수**를 센다. 이 숫자 하나를 `## 성숙도`에 둔다. 나머지 지표는 계측 소스가 있을 때만 추가한다 — 계측할 수 없는 지표를 문서에 적어두는 것이 바로 "안전으로 위장한" 상태다.

| 지표 | 계측 소스 |
|---|---|
| 에스컬레이션률 | `Notification`/`PermissionRequest` hook, OTel `tool_decision` — **네이티브 있음** |
| 가이드 증가율 (감소해야 정상) | `CLAUDE.md`/`.claude/rules/` git 히스토리 — **네이티브 있음** |
| 재작업률 | OTel `code_edit_tool.decision` — **OTel 필요** |
| 작업당 비용 | `-p --output-format json`의 `total_cost_usd` 또는 OTel — **대화형 transcript에 cost 필드 없음** |
| 완료율 / 복구시간 | **네이티브 소스 없음.** 하네스가 원장을 써야만 존재한다 — 지표가 아니라 산출물 요구사항으로 다룬다 |

## 테스트 시나리오

**정상 흐름.** 신규 Python 프로젝트에서 "하네스 구축해줘" → 결정 필터 5문항(반복=예, 무인=아니오, 수용기준=pytest 통과+커버리지 80%) → 1단계 감사(계층 0개) → 2단계 `CLAUDE.md`에 `pytest -q` / `ruff check .` 기록 후 실행해 종료코드 0 확인 → 3단계 두 명령을 에이전트 자기검증 루프에 배선, `settings.json` 라인 제시 → 4단계 에이전트 2개 + 오케스트레이터 생성, `_workspace/harness.md` 생성, 미검증 표식 부착 → 사용자에게 보고.

**에러 흐름.** 2단계에서 `pytest`가 종료코드 4(수집 실패)를 반환 → 명령이 틀렸거나 환경이 없는 것이므로 **다음 단계로 넘어가지 않는다.** 정확한 명령을 사용자에게 확인하고, 확인될 때까지 `CLAUDE.md`에 추측한 명령을 쓰지 않는다. 잘못된 build 명령이 적힌 가이드는 없는 가이드보다 나쁘다 — 모든 향후 세션이 그것을 신뢰하기 때문이다.

**기존 하네스 흐름.** "에이전트 하나 추가해줘" → 1단계 drift·dangling 감사 → 곧바로 4단계, 중복 검토 후 추가 → `harness.md` 변경 이력 갱신. 빌드 경로를 다시 밟지 않는다.
